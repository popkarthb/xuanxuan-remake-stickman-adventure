# 萱萱小游戏：火柴人大冒险重制版

**Stickman Adventure Remake**

一个根据童年回忆重新制作的火柴人冒险小游戏。

这个项目尝试把记忆中的火柴人探索、平台跳跃、射击、近战、钥匙、道具、机关和区域连接等玩法重新做出来，并在后续开发中逐步完善游戏内容和体验。

## 为什么做这个重制版

小时候，我曾经在萱萱那边打开过一款 Flash 火柴人小游戏，一玩就是一个下午。那个年代大约还是 2000 年前后，Flash 游戏刚刚开始成为很多人接触电脑游戏的一种方式。这个游戏虽然画面和操作都很简单，但它把探索、关卡、机关和解谜组合在一起，对当时的我来说非常新鲜，也留下了很深的印象。

很多年以后，我们希望借助现在的 Agent 和 Python，把记忆中的这款游戏重新复现出来。这个项目并不是要取代原来的作品，而是一次基于童年记忆的重制和致敬：尽量保留当年那种简单、直接、需要自己探索和思考的感觉，同时用今天的开发方式把它重新做出来。

也希望曾经玩过类似早期 Flash 游戏的玩家，能够通过这个项目重新感受到那个年代关卡解谜小游戏的设计方式和乐趣。

## 当前版本

当前原型已经按照童年记忆草图重建为 **8 个房间**，主要包括：

- 六门的多层中心房间
- 两门基础房间
- 带高低平台和大型台阶结构的房间
- 楼梯与单向高低层结构
- 浮动平台房间
- 道具房：枪、钻地工具、宝箱
- 三层门结构与大型高台
- 楼梯取钥匙房间
- 平台跳跃与左右奔跑动画
- 枪械与近战攻击
- 钥匙锁门
- 可破坏地板与钻地机制
- 支持单向门与多对一门连接

### 门连接

门的连接不是默认双向的。

每扇门都有独立的方向性 route，因此可以实现：

- A 房间进入 B 房间，但从 B 房间返回时去 C 房间
- 多扇不同的门都回到同一个中心出生点
- 从上层门进入后只能向下走，下面的门再返回大地图
- 需要钥匙才能进入的路线

当前 `levels.py` 中的 door mapping 是用于验证玩法的 **临时 Demo Routing**。正式的门对应关系会在后续关卡设计阶段继续调整。

## 项目结构

- `main.py`：游戏主循环、输入、物理、碰撞、战斗和渲染
- `models.py`：房间、门、方向性门连接、敌人、道具、可破坏平台等基础数据模型
- `levels.py`：地图布局、出生点、门连接、平台、敌人、钥匙和道具配置
- `image/`：公开的游戏截图与项目图片

后续设计或调整关卡时，优先修改 `levels.py`。地图内容和游戏引擎保持分离，避免把具体关卡配置重新堆回 `main.py`。

## 运行

```bash
python -m pip install -r requirements.txt
python main.py
```

## 操作

- `←` / `→` 或 `A` / `D`：移动
- `↑` / `W` / `Space`：跳跃
- `Z` / `J` / `Left Ctrl`：攻击
- 获得枪后：攻击键开枪，有弹药时优先使用枪
- 获得钻地工具后：站在可破坏地板上按 `↓` / `S` + 攻击键打穿地板
- `R`：重新开始
- `Esc`：退出

门本身不显示任何文字标签。锁门通过游戏状态和钥匙控制。

## 项目状态

当前项目处于早期重制与玩法验证阶段。房间形状已经开始按照童年记忆草图重建，但正式的关卡顺序、门对应关系、谜题流程、敌人配置和道具用途仍会继续迭代。
